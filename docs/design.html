02LAYERS

3つの役割分担

このゲームは「お話」「進み具合」「見た目」をはっきり分けています。分けておくと、お話を足すときはデータだけ、見た目を変えるときは画面だけを触ればよくなります。

DATA

お話の中身

data/scenario.js。セリフ・選択肢・背景・エンディングを、ただのオブジェクトとして書いた場所。Vue の機能は一切使っていません。

STATE

今どこまで進んだか

stores/game.js。今のシーン、何行目か、絆の値。データを読んで「次はどこか」を決めます。

VIEW

画面と演出

views/ と components/。ストアの値を表示し、クリックを受け取り、タイプライターやグリッチを担当します。

03ROUTER

ページ切り替え（Vue Router）

URL とページの対応を router/index.js に1か所で書いています。エンディングだけは URL の一部（:type）で、どのエンディングを出すかを受け渡します。

05PINIA

Pinia ストア

ゲーム画面とエンディング画面は別のページなので、コンポーネントの ref だけでは値を受け渡せません。ストアに置けば、どのページからでも useGameStore() で同じデータに触れます。書き方はコンポーネントとほぼ同じ形です。

Piniaコンポーネントでいうとこのゲームでは
staterefsceneId・lineIndex・bond（絆）
getterscomputedscene・line・isLastLine・showChoices・endingType
actions普通の関数reset()・next()・choose()・goToScene()
stores/game.js（抜粋）
getters: {
  scene: (state) => scenes[state.sceneId],
  line() {
    // getter から別の getter を使うときは this
    return this.scene.lines[this.lineIndex]
  },
  endingType: (state) => {
    if (state.bond >= 3) return 'true'
    if (state.bond === 2) return 'good'
    return 'lost'
  },
},
actions: {
  next() {
    if (!this.isLastLine) this.lineIndex++
    else if (this.scene.next) this.goToScene(this.scene.next)
  },
  choose(choice) {
    this.bond += choice.points
    this.goToScene(choice.next)
  },
}

ストアはページ移動（router.push）をしません。「どこまで進んだか」だけを管理し、画面の移動はページ側（GameView）が決めます。こうしておくと、ストアは画面のことを知らずに済みます。

06FLOW

1クリックの流れ

画面をクリックすると GameView の onNext() が呼ばれます。判定は上から順に4つです。

flowchart TD
  click(["画面をクリック"]) --> typing{"文字を表示中？"}
  typing -- はい --> finish["全文を一気に表示"]
  typing -- いいえ --> choices{"選択肢が出ている？"}
  choices -- はい --> wait["何もしない
（ボタンを押してもらう）"]
  choices -- いいえ --> isEnd{"最後のシーンの
最後の行？"}
  isEnd -- はい --> push["router.push
/ending/ + endingType"]
  isEnd -- いいえ --> next["game.next()
次の行 or 次のシーン"]
  next --> watch["watch が line の変化を検知
タイプライター開始"]
views/GameView.vue
function onNext() {
  if (isTyping.value) { finishTyping(); return }
  if (game.showChoices) return
  if (game.isLastLine && game.scene.end) {
    router.push(`/ending/${game.endingType}`)
    return
  }
  game.next()
}

選択肢のボタンは @click.stop の付いた枠の中にあります。これがないと、ボタンのクリックが外側の画面にも伝わり、選んだ瞬間に1行先へ進んでしまいます。

07EFFECTS

演出のしくみ

演出は「Vue で状態を切り替え、見た目は CSS に任せる」形でそろえています。Vue 側でやっているのは、値を変えることとクラスを付け外しすることだけです。

演出Vue の機能場所
文字が1文字ずつ出るref + computed + watch + setIntervalGameView
画面が乱れる（グリッチ）watch でシーン変化を検知 → :classGameView
観測計の数字が回るwatch で props の変化を検知NixieMeter
背景・立ち絵のフェード<Transition> + :keyStageLayer
残響（青白く透けて点滅）props の echo → :classStageLayer

タイプライター

「何文字目まで出したか」だけを ref で持ち、表示する文字列は computed で切り出します。セリフが変わったら watch が数え直しを始めます。

const typedLength = ref(0)
const typedText = computed(() => game.line.text.slice(0, typedLength.value))
const isTyping = computed(() => typedLength.value < game.line.text.length)

// immediate: true で、画面を開いた最初の1回も実行する
watch(() => game.line, startTyping, { immediate: true })

グリッチ

シーンに glitch: true があれば、1秒だけ glitching を true にします。揺れや色ずれは CSS の @keyframes（transform と filter: hue-rotate / invert）が担当します。

watch(() => game.sceneId, () => {
  if (!game.scene.glitch) return
  glitching.value = true
  glitchTimer = setTimeout(() => (glitching.value = false), 1000)
})

観測計（ニキシー管）

表示用の shown を別に持ち、新しい値が来たら60ミリ秒ごとにランダムな数字を15回出してから本当の値で止めます。光のにじみは text-shadow を3重に重ねて作っています。

タイマーの後片付け

setInterval や setTimeout を使うコンポーネントはすべて、onUnmounted でタイマーを止めています。ページを離れても動き続けるタイマーは、よくあるバグの原因になります。

08BUGFIX

立ち絵が重なるバグと :key

表情が変わるたびに、ずんだもんが一瞬2人に見えるバグがありました。原因は <Transition> に渡す :key の選び方です。

BEFORE 
<Transition name="fade">
  <img :key="charaSrc" … />
</Transition>

key が画像のパスなので、表情が変わるたびに「別の画像」とみなされます。古い画像のフェードアウトと新しい画像のフェードインが同時に0.6秒起き、腕の位置が違う2枚が重なって見えていました。

AFTER 
<Transition name="chara-fade" mode="out-in">
  <img :key="charaKey" … />
</Transition>

key をキャラ名（'zun_smile' → 'zun'）にしました。表情が変わっても同じ要素のまま src だけが差し替わります。別のキャラに替わるときは mode="out-in" で、消えきってから次が出ます。

const charaKey = computed(() => props.chara?.split('_')[0])

ポイントは、:key が「Vue が同じものとみなす単位」を決めているということです。アニメーションさせたい単位を key にします。

10DECISIONS

設計の判断

お話はコードではなくデータで書く

シナリオを scenario.js のオブジェクトにしたので、シーンを足すときに Vue のコードを触る必要がありません。分岐もエンディングも同じ形のデータで表せます。

画像はファイル名ではなく「名前」で指定する

シナリオには 'zun_sad' とだけ書き、パスの組み立ては StageLayer が担当します。フォルダや拡張子を変えても、直す場所は1か所です。

エンディングは URL で渡す

/ending/true のように URL に結果を入れたので、エンディング画面はストアがなくても表示できます。直接 URL を開けば、各エンディングの見た目を確認できます。

演出の判定は Vue、動きは CSS

グリッチや残響の動きは CSS アニメーションに任せ、Vue はクラスを付け外しするだけです。JavaScript でフレームごとに動かすより短く、止め忘れも起きません。

背景と立ち絵の表示を1つの部品にまとめる

StageLayer をゲーム画面・エンディング・タイトルで使い回しています。フェードや残響の演出が、どの画面でも同じように動きます。
