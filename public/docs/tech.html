03PINIA

Pinia：進み具合と分岐

ゲーム画面・分岐図・エンディングは別のページなので、ref だけでは値を受け渡せません。ストアに置けば、どのページからでも useGameStore() で同じデータに触れます。

Piniaコンポーネントでいうとこのゲームでは
staterefsceneId・lineIndex・path・visited・movie
getterscomputedline・lines・visibleChoices・endingType・endingsSeenCount
actions普通の関数next()・choose()・goToScene()・jumpTo()

分岐は「選んだ番号の文字列」

選択肢を選ぶたびに、その番号を path に1文字ずつ足します。3回選ぶと '101' のような3桁になり、それでエンディングが決まります。

stores/game.js
choose(choice) {
  const index = this.scene.choices.indexOf(choice)
  this.path += index          // '' → '1' → '10' → '101'
  this.markVisited(this.path) // 通った分岐を localStorage に記録（分岐図が光る）
  this.goToScene(choice.next)
},

セリフの when: '?1' は「2回目に1番を選んだときだけ出す」という条件です。? はどちらでもよい印で、1文字ずつ比べるだけで判定できます。

export function matchesWhen(when, path) {
  if (!when) return true
  return [...when].every((ch, i) => ch === '?' || path[i] === ch)
}

// getter：今のシーンのセリフのうち、条件に合うものだけ
lines() {
  return this.scene.lines.filter(
    (l) => matchesWhen(l.when, this.path) && (!l.replay || this.endingsSeenCount > 0),
  )
},

replay: true は2周目以降だけ出るセリフ、secret: true の選択肢は8つのエンディングを全部見たあとだけ出ます。どちらも getter の filter 1つで実現しています。開発中は acceptHMRUpdate を書いておくと、ストアを直したときに古い中身が残りません。

演出の指定もシナリオのデータに書きます。画面側は「その項目があれば部品を出す」だけです。新しい演出を足すときは、部品を1つ作り、GameView に1行足し、シナリオに項目を書きます。

<ScanLock v-if="game.line.scan && !blocking" :key="`s-${lineId}`"

短い書き方を computed でそろえる

カットインは cutin: 'eyes' とも cutin: { type: 'diagonal', angle: -16 } とも書けます。部品に渡す前に computed で同じ形にそろえるので、部品の側は1種類の形だけを考えれば済みます。

const cutin = computed(() => {
  const c = game.line.cutin
  if (!c) return null
  const base = typeof c === 'string' ? { type: c } : c
  return { chara: game.line.chara, echo: game.line.echo, ...base } // キャラは省略したらセリフのもの
})
05REACTIVITY

ref・computed・watch の使い分け

道具使いどころこのゲームの例
ref変わる値を持つ何文字目まで出したか（typedLength）・マウスの位置
computedほかの値から計算できるもの表示する文字（typedChars）・文字を出している途中か
watch値が変わった「とき」に何かするセリフが変わったらタイプ開始・効果音を鳴らす

タイプライター

持つのは「何文字目まで出したか」だけです。表示する文字は computed で切り出し、句読点では setTimeout の待ち時間を長くして、間を作っています。

views/GameView.vue
const chars = computed(() => parseRichText(lineText.value)) // *強調* などを1文字ずつに
const typedLength = ref(0)
const typedChars = computed(() => chars.value.slice(0, typedLength.value))

function typeNext() {
  typedLength.value++
  if (!isTyping.value) return
  const factor = SPEED[game.line.speed] ?? 1
  typeTimer = setTimeout(typeNext, pauseAfter(chars.value[typedLength.value - 1].ch) * factor)
}

// セリフが変わったら最初から。immediate で、画面を開いた最初の1回も実行する
watch(() => [game.line, blocking.value], startTyping, { immediate: true })

タイマーは必ず片付ける

setTimeout・setInterval・requestAnimationFrame・addEventListener を使う部品はすべて、onUnmounted で止めています。ページを離れても動き続けるタイマーは、よくあるバグの原因です。

06TRANSITION

<Transition> と :key

:key は「Vue が同じものとみなす単位」を決めます。key が変わると別の要素として作り直され、<Transition> の出入りアニメーションがかかります。演出ではこれを2つの向きで使っています。

BEFORE：立ち絵が2人に見える 
<Transition name="fade">
  <img :key="charaSrc" />
</Transition>

key が画像のパスなので、表情が変わるたびに「別の画像」になり、古い絵と新しい絵が重なってフェードしていました。

AFTER：キャラ単位で切り替え 
<Transition name="chara-fade" mode="out-in">
  <CharaSprite :key="charaKey" :name="chara" />
</Transition>
// 'zun_smile' → 'zun'
const charaKey = computed(() => props.chara?.split('_')[0])

表情の変化では同じ要素のまま。別のキャラに替わるときだけ、out-in で消えきってから次が出ます。

逆に、毎回作り直したいとき

カットインやスキャンは、セリフが変わるたびにアニメーションを最初から再生したいので、セリフの ID を key にしています。key が変わると部品が作り直され、CSS アニメーションも頭から始まります。

<CutIn v-if="cutin && !blocking" :key="`c-${lineId}`" :cutin="cutin" />

背景は <Transition name="fade"> で重ねてクロスフェード、立ち絵は out-in で順番に。何を重ね、何を順番にするかは mode で決まります。

07COMPOSABLES

コンポーザブル：使い回す機能

useSound() のように use〇〇 という関数に機能をまとめると、どの部品からでも同じ道具を呼び出せます。ポイントは、関数の外に置いた値は全部の部品で共有され、関数の中で作った値は呼ぶたびに別になることです。

composables/audioCore.js
// 関数の外に置くと、どのコンポーネントから使っても同じ値を共有できる
export const muted = ref(loadMuted())

let ctx = null  // AudioContext はページに1つで十分なので、1つだけ作って使い回す
コンポーザブル中身共有しているもの
useSound効果音・雨の音音量つまみ・雨の音のループ
useMusicBGM の自動演奏・曲の「演技」今流れている曲
useArchive見たスチル・解放した TIPS記録（localStorage と同期）

Pinia のストアとの違い：ストアは「ゲームの進み具合」という1つの大きな状態、コンポーザブルは「道具」です。音のミュートのように小さな共有値なら、コンポーザブルの外側に ref を置くだけで足ります。

08SCOPED CSS

scoped CSS の注意点

<style scoped> の CSS は、その部品の要素だけに効きます。Vue が要素に data-v-6283c8e1 のような印を付け、セレクタにも同じ印を足して絞りこむしくみです（ブラウザの開発者ツールで見える謎の文字列はこれです）。

親から子の部品に CSS を当てたいとき

立ち絵の部品（CharaSprite）は、自分で残響のゆらめきアニメーションを持っています。親の StageLayer から「不在の残像」用のアニメーションを当てても、子の指定に負けて効きませんでした。親の側でセレクタを長くして強くすることで解決しています。

components/StageLayer.vue
/* 立ち絵の影の指定より優先させるため、セレクタを長くしている */
.layer-chara .absence {
  filter: grayscale(1) brightness(1.8) blur(1.5px);
  animation: absence 5s ease-out forwards;
}

CSS は「より具体的なセレクタ」が勝ちます（詳細度）。!important で無理に勝たせるより、何と何がぶつかっているかを開発者ツールで確かめてから、セレクタで勝たせるほうが後で困りません。

10CSS ANIMATION

CSS アニメーション：判定は Vue、動きは CSS

Vue がやるのは「クラスを付ける・外す」「部品を出す・消す」だけで、動きは @keyframes と transition に任せています。JavaScript で毎フレーム動かすより短く書け、止め忘れも起きません。

演出CSS の手法
カメラが寄る・傾く（close / dutch）transition: transform 1.4s で scale・rotate を変える
足元から見上げる（tilt-up）@keyframes で translateY と scale を戻す
手持ちカメラの揺れ9秒の不規則なキーフレームを infinite で
カットインが飛びこむtranslateX ＋ skewX ＋ blur から元へ（モーションブラーの見立て）
文字が回転しながら飛び出す1文字ずつ span にして、CSS 変数 --rx で角度を変える
世界の書き換えclip-path: inset() を動かして、見える範囲を線と一緒に下げる

同じアニメーションをもう一度再生する

クラスを付けっぱなしだと、アニメーションは1回しか動きません。一度外して、次の描画（約16ms後）で付け直すと、最初から再生されます。

components/StageLayer.vue（カメラが切り替わるたびの「カット」）
watch(() => [props.chara, props.camera], () => {
  cutting.value = false
  cutTimer = setTimeout(() => {
    cutting.value = true                                   // 付け直す
    cutTimer = setTimeout(() => (cutting.value = false), 520) // 終わったら外す
  }, 16)
})

動きを分けて重ねる

1つの要素の transform には、1つの動きしか書けません。「マウスで回る」「カメラワーク」「手持ちの揺れ」「カット」を同時に効かせるため、箱を入れ子にして、それぞれの箱に1つずつ動きを持たせています。

.handheld-box  ← 手持ちカメラの揺れ
  .cut-box     ← カットの瞬間の寄り
    .orbit-box ← マウスで舞台ごと回る
      .camera  ← カメラワーク（push・orbit など）
11CSS 3D

CSS 3D の舞台

背景・立ち絵・光の玉を、本当に奥行きの違う位置に置いています。マウスで舞台ごと回すと、遠いものほど大きくずれ、1枚の絵なのに奥行きが生まれます。

components/StageLayer.vue
.stage { perspective: 1000px; }  /* 1000px 離れた所からのぞいている */

/* 途中の箱すべてに付けないと、そこで平らにつぶれてしまう */
.handheld-box, .cut-box, .orbit-box, .camera { transform-style: preserve-3d; }

.layer-bg   { transform: translateZ(-320px) scale(1.42); } /* 奥。小さく見えるぶん拡大 */
.layer-near { transform: translateZ(220px); }              /* 手前の光の玉 */

.orbit-box {
  transform: rotateY(calc(var(--mx, 0) * 5deg)) rotateX(calc(var(--my, 0) * -3deg));
}

マウスの位置は GameView が -1〜1 にして CSS 変数 --mx・--my で渡しています。Vue から CSS へ値を渡すには、:style="{ '--mx': mouse.x }" のように CSS 変数にするのが手軽です。

3D のカメラワーク

カメラしくみ見え方
orbitカメラの箱を rotateY で -12° → 9°キャラはほぼそのまま、背景だけが大きく流れる＝回りこみ
cranerotateX(18deg) から正面へ上から降りてくる
vertigoperspective 自体を 2600px → 420px にアニメーションキャラの大きさは変わらず、背景だけが遠のく（めまいショット）

vertigo は「奥行き 0 の位置にあるものは、perspective を変えても大きさが変わらない」という性質を使っています。立ち絵は奥行き 0、背景だけが奥にあるので、背景だけが伸び縮みします。

3D を平らにつぶしてしまうもの

途中の箱に filter・overflow: hidden・opacity（1未満）を付けると、そこで 3D が平らになります。カットの瞬間のぼかしを箱ではなく中の層に付けているのは、このためです。

12CUT-IN

カットイン：立ち絵を巨大にして窓からのぞく

目のアップ用の画像は用意していません。ふつうの立ち絵を何倍にも拡大して、見せたい場所（目・口・片目）が窓の真ん中に来るようにずらしているだけです。なので、アップの中でもまばたきや口パクがそのまま動きます。

components/effects/CutIn.vue
// face.x / face.y … 立ち絵の中の、両目の中心の位置（0〜1）。faces.js にキャラごとに書いてある
// eyeSpan … 両目の幅（立ち絵の幅に対する割合）
const spriteW = Math.min(viewW * f.fill, panelH * f.maxH) / (face.eyeSpan * f.part)
const spriteH = spriteW / face.aspect
return {
  height: `${spriteH}px`,
  left: `${panelW / 2 - cx * spriteW}px`, // 見せたい点が窓の中心に来るように
  top:  `${panelH / 2 - cy * spriteH}px`,
}

「両目の幅が、窓の幅の何割になるか」から拡大率を逆算しています。ただし横長すぎる画面では顔が帯からはみ出すので、窓の高さでも上限をかけています（Math.min）。

種類窓の形Web の手法
eyes / face横長の帯窓に overflow: hidden
diagonal / slash斜めの帯（1本・2本）画面より長い帯を rotate（端が見えないように）
vertical / triptych縦長の帯で片目・3分割同じ立ち絵を、見せる場所を変えて3枚並べる
split左右に2人clip-path: polygon() で境目を斜めに切る

斜めの帯は「傾き」を外側の箱、「滑りこむ動き」を内側の箱に分けています。同じ要素の transform に両方書くと、アニメーションが傾きを上書きしてしまうからです（10章の「動きを分けて重ねる」と同じ考え方）。

13CANVAS

Canvas とタイムリープ

要素が数百個になる演出（数字の雨・光の筋）は、DOM ではなく <canvas> に描いています。DOM の要素を数百個動かすより、1枚の絵に毎フレーム描き直すほうが速いからです。

01 SUCK吸いこまれる

CSS アニメーション。景色が 3回転しながら scale(0.01) まで縮み、後ろで repeating-conic-gradient の渦が回る

02 LEAP時間のトンネル

Canvas。光の筋・時計の輪・通りすぎる景色・数字の雨。速さがどんどん上がり、最後は白く飛ぶ

03 ARRIVE着地

CSS アニメーション。ぶれた景色が止まり、赤と青にずれた絵が重なり（色収差）、衝撃の輪が広がる

奥行きの計算は「割り算」だけ

奥にあるもの（z が大きい）ほど、中心に寄せて小さく描きます。これが遠近法の正体です。毎フレーム z を減らすと、点が手前へ飛んできます。

components/TimeLeap.vue
function project(a, r, z) {
  const s = F / z  // 遠いほど s が小さい
  return [cx + Math.cos(a + spin) * r * s, cy + Math.sin(a + spin) * r * s, s]
}

// 今の位置と、少し奥の位置を線でつなぐ → 速いほど長い線（光の筋）になる
const [x1, y1] = project(st.a, st.r, st.z)
const [x0, y0] = project(st.a, st.r, st.z + v * 0.09)

残像はわざと消し残す

毎フレーム画面を真っ黒に消さず、半透明の黒を重ねるだけにしています。前のコマが少しずつ薄れて残り、それがスピード感と数字の雨の尾になります。

ctx.fillStyle = 'rgba(3, 4, 12, 0.3)' // 完全には消さない
ctx.fillRect(0, 0, c.width, c.height)

描画ループは requestAnimationFrame でつなぎ、onUnmounted で cancelAnimationFrame します。進み具合は経過時間（performance.now()）から計算するので、処理が重くてコマが落ちても、全体の長さはずれません。ムービーのカットの切り替えは setTimeout で進めています。アニメーションの終わりを待たないので、別のタブを見ていても止まりません。

14FILTER & BLEND

フィルターと合成

背景や立ち絵の色・質感は、画像ファイルを作り直さずに、表示するときにブラウザで加工しています。同じ素材のまま、場面ごとに雰囲気を変えられます。

手法何ができるか使っている所
filter色・明るさ・ぼかし・影シーンの色調補正（grade）・背景のぼけ・残響の光

合成は z-index の箱に閉じこめられる

世界の書き換えは、最初 backdrop-filter で白黒にしようとしましたが、3D の舞台の上では効きませんでした。そこで「鮮やかさ 0 の黒い板を saturation で重ねる」方法に変えています。

/* この箱には z-index を付けない（付けると、中の層が後ろの画面と混ざり合えなくなる） */
.rewrite { position: absolute; inset: 0; }
.old { background: #000; mix-blend-mode: saturation; } /* 明るさはそのまま、色だけ 0 に */

mix-blend-mode は、同じ「重なりのグループ（スタッキングコンテキスト）」の中のものとしか混ざりません。親に z-index や filter があると、そこでグループが閉じてしまいます。

15COMPOSITING

キャラを背景になじませる

背景は 3DCG、立ち絵は手描きと、絵の作り方がまったく違います。絵は加工せず、「同じ光・同じ色・同じ空気の中にいる」条件を CSS でそろえています。

  1. 同じ色をかける：背景と立ち絵を1つの箱（.grade）に入れ、箱ごと filter で色調補正。キャラだけ色が浮かない
  2. 同じ光を当てる：光の筋を立ち絵より手前に置き、screen で重ねる
  3. 同じ質感をかける：いちばん上の .post でビネット・走査線・動くざらつき
  4. 輪郭をぼかす：立ち絵に drop-shadow(0 0 12px rgba(0,0,0,.6))。切り抜いたような縁が消える
  5. 空間の中に置く：背景は奥、光の玉と雨は手前。顔に寄るときは背景だけぼかす（被写界深度）
  6. 止めない：呼吸（4.2秒で縦に 1.2% 伸びる）・まばたき（2〜6秒ごと）・口パク

試すなら：ブラウザで F12 → Console に document.querySelector('.post').style.display = 'none'。キャラが急に「貼り付けた絵」に見えます。

まばたきと口パクは「重ねて出し消し」

表情ごとに「ふつう」「目を閉じた絵」「口を開けた絵」の3枚を重ねておき、上の2枚の opacity を切り替えています。src を差し替える方法だと、画像の読み込みで一瞬チラつくからです。

16WEB AUDIO

Web Audio：音声ファイルなしで音を作る

効果音も BGM も、音声ファイルは1つも使っていません。ブラウザの Web Audio API で、その場で波形を作って鳴らしています。

部品Web Audio の道具作れる音
toneOscillatorNode（サイン波・のこぎり波など）ピッ・ドン・耳鳴り
noise乱数で埋めた AudioBuffer ＋ BiquadFilterザーッ・雨・雷
drone / sweepGainNode の音量の変化（エンベロープ）吸いこまれる音・タイムリープのうなり
composables/useSound.js
function tone(c, { freq, to = freq, dur, type = 'sine', vol = 0.1, delay = 0 }) {
  const t = c.currentTime + delay
  const osc = c.createOscillator()
  const gain = c.createGain()
  osc.type = type
  osc.frequency.setValueAtTime(freq, t)
  osc.frequency.exponentialRampToValueAtTime(to, t + dur) // 音の高さを動かす
  gain.gain.setValueAtTime(vol, t)
  gain.gain.exponentialRampToValueAtTime(0.0001, t + dur) // だんだん消える
  osc.connect(gain).connect(sfxBus)
  osc.start(t)
  osc.stop(t + dur)
}

BGM は「先読みスケジューラ」

setInterval の時間は正確ではないので、それで直接音を鳴らすとリズムがよれます。50ms ごとに「0.25秒先までの音符」を AudioContext の正確な時計（currentTime）で予約しておく方式にしています。曲はコード進行とメロディのデータから組み立てます。

曲に「演技」をさせる

セリフの music で、曲全体にかけたローパスフィルターと音量を動かします。

music音量フィルター使いどころ
duck0.35そのまま大事なセリフの下で小さく
muffle0.8450Hz（こもる）水の中のような遠さ
cut0（0.06秒で）そのままぞっとする瞬間の無音
swell1.5（3秒かけて）そのまま感情の山場

ブラウザは「ユーザーが何か操作するまで音を出さない」決まりがあります。AudioContext は初めて音が必要になったときに作り、止まっていたら resume() で再開しています（audioCore.js の getAudio()）。

17ROBUSTNESS

壊れにくくする工夫

  • 動きを減らす設定に従う：OS で「視差効果を減らす」を選んでいる人には、@media (prefers-reduced-motion: reduce) でアニメーションを止め、ムービーも短くしています。JavaScript では matchMedia で同じ判定ができます
  • 保存は失敗してもいい形に：localStorage はプライベートモードなどで使えないことがあるので、読み書きを try / catch で囲み、使えなくても遊べるようにしています
  • 画像の先読み：ムービーのカットは、始まる前に new Image().src = … で読みこんでおき、切り替わった瞬間に絵が遅れて出ないようにしています
  • 別のタブを見ている間：ブラウザは裏のタブのタイマーやアニメーションを止めたり遅らせたりします。制限時間つきの選択肢は document.hidden のあいだカウントを止めています
